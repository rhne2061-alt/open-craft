# ADR 0001：采用 Git 目录与静态站点

状态：v0.1 采用，可按社区反馈修改。

背景：目前是新社区、少量资源和单一维护入口，需要快速建立可贡献、可取用、可 Fork 的项目。资源以设计与源码为主，不需要实时用户状态。

比较：

1. Astro + Git + 静态托管：维护简单、内容可审查，无实时账户和上传体验。
2. 全栈框架 + PostgreSQL + 对象存储：更适合账户、收藏与投稿后台，但增加权限、数据库、运维与费用。
3. 现成低代码平台：上线快，但可能限制源码归属和贡献流程。

决定：采用方案 1；只为实际交互附加客户端 JS。目录协议与 UI 分离，后续 MCP 可以复用数据，无需先迁移存储。

约束：人工审核仍是瓶颈；大资源库的客户端索引需要分片；静态托管并非无限免费。首版只接收 HTML/CSS，复杂 JS 预览在独立 origin 环境落地后另作决策。

重新评估时机：资源规模导致搜索负担、非技术贡献者投稿明显受阻，或社区明确需要用户状态时。不要仅为假设中的规模提前建设服务。
